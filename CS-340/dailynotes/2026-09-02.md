# TypeScript

TypeScript is JavaScript + types. Code written in TS is "compiled" into JS. (Formally, TS is a ***transpiler***.)

## JS vs. TS typing

### JS typing

JS's dynamic typing is peepee poopoo for writing big software.

JS also has some weird conversion rules. e.g., `3 + [1]` is equal to `3.toString() + [1].toString()` in JS.

### TS typing

- TS uses **STATIC typing**. You cannot change the type of a variable aefter you've declared it.
- TS does support **type inference**, meaning you can let the compiler figure out the value's type. Hence, **type annotations are optional**.

Type annotations look like this:

```
let var: type = value;
```

## TS data types

- `undefined`: Represents the ABSENCE of a value. 
  - Uninitialized vars are `undefined`.
- `null`: Represents a value of NO VALUE.
  - Most useful for object references that aren't pointing at anything yet.
- Basic types: 
  - `boolean`
  - `string`
    - Strings can be concatenated w/ `+`/
    - Strings can be interpolated w/ backticks.
  - `number`: 8-byte float
    - You can use numeric seperators (`_`) to make bigger numbers more readable. e.g., `const OneMillion = 1_000_000`.
  - `bigint`: can represent ANY number, no matter how big.
    - Not efficient.
    - Bigints literals are represented w/ an `n` postfix. e.g., `let a: number = 1000000n`
  - `enum`: Datatypes w/ restricted domain of (symbolic) values.
    - Values are typically inferred (ints `0` and on), but you can also explicitly assign your own to them.
      - You can even mix different types for the values you assign
  - `any`: NO TYPE. Opts out of TS's static type checking.
    - On an `any`, you can access any property or call any method.
    - SHOULD BE AVOIDED. It's intended only to use when you know the environment better than TS would.
      - e.g., when using a JS library that doesn't have TS type definitions. 
    - Useful when you don't want to write out a long type just to make TS happy. (Ts is practice tho.)
  - `unknown`: Indicates you don't know value's type.
    - An `unknown` var cannot be used until it is casted.
      - You must figure out what type it is yourself (using type assertions (`===`)).
  - `object`: Points to any object of any type.

### Objects

- Indicated w/ `{}`.
- `name: value`.
- You can even do object type annotations, which look like a curly-braced list of `name: type` pairs (see below).
- Objects can be nested w/in other objs.

TS uses what's called "structural typing", meaning **two objects are compatible if they have the same "shape"**. (Idk what "shape" means...)

You may not leave properties out and you may not add new properties.

#### Type annotation

Here's an example of an object type annotation:

```
let stock: { sym: string, price: number } = { sym: 'AAPL', price: 137.23 };
```

#### Optional members

You can add a `?` postfix to a member's name to make it optional. If you don't define the value of an optional member, it will be assigned `undefined`.

### Type aliases

You can declare a type alias via <code>type <i>alias</i> = <i>T</i></code>

### Unions & Intersections

- Intesrection: `T1 & T2`.
  - An obj defined as `T1 & T2` contains ALL members of `T1` AND `T2`.
- Union: `T1 | T2`.
  - An obj defined as `T1 | T2` may be a `T1`, a `T2`, or both (union).
    - i.e., it might contain all of `T1`'s members, all of `T2`'s members, or all of both.

### Arrays

- Typed like this: <code><i>type</i>[]</code>
- Array literals are enclosed in square brackets (`[]`).
- Arrays elements must share the same type&mdash;though they may be a union or intersect type (see below).

### Tuples

Fixed-length, ordered arrays. 

- Each element has a fixed type. 
- Tuples have to be explicitly typed. (`[]` literals are always inferred to be arrays.)
- Tuples support **rest elements** (`...`).

### Literal types

Literals/constants are both values AND types. (HUH?)

e.g., if you declared `const myVar = "howdy";`, its type would be `"howdy"`, a sub-type of `string`.

Most of the time you won't have to care about this, but this is an important thing to remember when reading error messages.

## Functions

### Typing

You can optionally define the types of params & returns.

<code>function <i>func</i>(<i>param1</i>: <i>T1</i>, <i>param2</i>: <i>T2</i>, <i>...</i>): <i>returnType</i> {}</code>

A function that returns nothing is typed as `void`.

### Parameters

You can add a `?` postfix to a param name to indicate it's an optional parameter. Thus, a value does not need to be supplied to that param to call it.

You can assign a default value to a parameter the same way you do in C++.

You can also have rest params (`...`). To the caller, they don't have to put their inputs as an array, but to the function, that param is an array. (Idk if ts makes sense... whatever.)

### Function types

Functions themselves have a type. The param types & return type together form the function's type.

Function types are specified like this: <code>(<i>param1</i>: <i>T1</i>, <i>param2</i>: <i>T2</i>, <i>...</i>) => <i>returnType</i></code>

Function types are especially useful for callbacks 'n shih (passing functions into other functions 'n shih). In this case, you'll often alias the function type and then define a callback parameter's type using that alias.
